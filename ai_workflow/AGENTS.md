# Workflow tools — instructions for an AI agent

You control an image/video generation system through six tools. You are the planner and operator; the
generation happens elsewhere (ComfyUI on a Google Colab runtime, reading and writing a Google Drive folder).
You never need a node id, a model file name, a GPU type, or any API key.

These instructions are the same for every assistant. Nothing here depends on which one you are.

## The tools

Run them with any Python 3.11+ (standard library only). Output is JSON on stdout; exit code 1 means
`{"ok": false, "error": {"code", "message", "hint"}}`.

```
python scripts/aiwf.py list-workflows
python scripts/aiwf.py create-job WORKFLOW --prompt "..." [--set NAME=VALUE ...] [--attest INPUT]
python scripts/aiwf.py status JOB_ID
python scripts/aiwf.py list-jobs [--status pending|running|completed|failed|cancelled] [--limit N]
python scripts/aiwf.py cancel JOB_ID
python scripts/aiwf.py result JOB_ID [--wait SECONDS]
```

| Tool | Command | What it does |
| --- | --- | --- |
| `list_workflows()` | `list-workflows` | Workflows, and for each one the parameters and file inputs it takes (type, range, default). |
| `create_job()` | `create-job` | Validates and queues a job. Returns `job_id`. Costs nothing by itself. |
| `get_job_status()` | `status` | `pending` / `running` / `completed` / `failed` / `cancelled`, plus whether a worker is alive. |
| `list_jobs()` | `list-jobs` | Jobs in the workspace, with counts per status. |
| `cancel_job()` | `cancel` | Requests cancellation (a queued job is dropped, a running one is interrupted). |
| `get_result()` | `result` | The output of a completed job: path in the workspace, local path, size, duration. |

The path to `scripts/aiwf.py` is either inside the synced workspace folder (`AI-Workflow/scripts/aiwf.py`,
no configuration needed) or in the repository (`ai_workflow/scripts/aiwf.py`, which reads the workspace
location from `ai_workflow/configs/local.json` or `--root`). From Python you can also
`from controller import tools` and call the six functions directly.

## How to handle a request

1. `list-workflows` — pick the workflow whose `type` and `task_types` match (image → `z-image-basic`,
   video → `minimax-h3-basic`). Read its parameters; do not guess names.
2. `create-job` — send the user's prompt as written, plus only the parameters they asked for. Leave the rest
   to the defaults. `--set NAME=VALUE` values are JSON when they parse as JSON (`steps=8`, `solo=true`),
   text otherwise (`aspect=16:9`).
3. `status` — if the answer has a `hint`, **tell the user what it says**: a person has to open a notebook in
   Google Colab and press Run all (you cannot start the GPU runtime, and it costs their compute units). Do not
   poll in a tight loop while no worker is alive.
4. `result --wait 600` once a worker is running. A video with a generated first frame is two jobs
   (`jobs` in the create-job answer); wait on the one in `job_id`.
5. Report: status, output path (`output.local_path` when `available_locally` is true), size or duration,
   `generation_seconds`. If the job failed, report `error.code` and `error.message` as they are.

Example — "make a 5 second product video":

```
python scripts/aiwf.py create-job minimax-h3-basic --prompt "A matte black wireless earbud case on a white table. The lid opens slowly. The camera remains static." --set duration=5 --set aspect=16:9
python scripts/aiwf.py result job-20261002-101500-ab12cd --wait 1800
```

## Rules

- **User intent over prompt polish.** Improve grammar and add detail the user would agree with; never change
  what they asked for, and never add motion, camera moves or subjects they did not ask for.
- **Do not work around a refusal.** `PROMPT_REJECTED`, `UNSAFE_JOB`, `ATTESTATION_REQUIRED` and a `cfg` below
  1.5 are refused on purpose. Report them; do not rephrase to get past the filter and do not edit job files.
- **A first frame from `inputs/`** (`--set first_frame=inputs/x.png`) needs `--attest first_frame`. Add it
  only after the **user** has confirmed the image is one generated by this project (a fictional adult
  character) or contains no person — never a photo of a real person. You cannot confirm that yourself.
- **Only use the six tools.** Do not write, move or edit files under `jobs/`, `outputs/`, `models/` or
  `workflows/` directly: the folder is synced between two machines and only the worker may move a job file.
  Adding a new workflow (a graph JSON plus a `workflows/registry.json` entry) is a task for the user to ask for
  explicitly.
- **Never retry a failed or timed-out job automatically**; ask first. Runs cost compute units.
- All people in prompts are adults. Explicit content is out of scope.

## Error codes you will see

| Code | Meaning |
| --- | --- |
| `WORKSPACE_NOT_FOUND` | The workspace folder is not configured or not synced; the `hint` says how to set it. |
| `UNKNOWN_WORKFLOW` | No enabled workflow by that name; `hint` lists the names. |
| `INVALID_INPUT` | A parameter is missing, out of range or unknown; the message names it. Nothing was queued. |
| `PROMPT_REJECTED` | The prompt contains a term that is never sent to a model without a negative prompt. |
| `ATTESTATION_REQUIRED` | A file from `inputs/` was given without the user's confirmation of its origin. |
| `JOB_NOT_FOUND` | No such job in this workspace. |
| `DEPENDENCY_FAILED` | The job this one needed (a video's first frame) did not complete. |
| `INPUT_NOT_FOUND`, `INPUT_CHANGED` | The input file is missing, or is no longer the file its job wrote. |
| `MODEL_CHECKSUM`, `DISK_FULL`, `NODE_CHECK_FAILED`, `COMFYUI_START_FAILED` | Setup failed on the runtime; report the message. |
| `COMFY_REJECTED`, `COMFY_EXECUTION_ERROR`, `OUTPUT_NOT_FOUND`, `JOB_FAILED` | The generation failed; report the message. |
| `TIMEOUT` | No output within the workflow's time limit; the job was interrupted. Do not resubmit without asking. |
| `INVALID_OUTPUT` | A file was produced but failed validation; it was not stored. Never call it a success. |
| `SESSION_LOST` | The runtime disappeared twice while this job ran. |
| `CANCELLED` | The job was cancelled. |

A job that stays `pending` with a `waiting` reason ("needs a GPU with at least 38 GiB VRAM") is not failed:
the open runtime is too small for it. Tell the user which GPU the workflow needs.
